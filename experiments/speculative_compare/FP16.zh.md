# FP16 Target 短对照

用户决定先切换 Target 主干为 FP16。新增入口是 `run_fp16_regression.sh`，不调用 `start.sh`、`setup.sh`、原 `run_gpu.sh`，不重新下载、安装或修改权重文件，也不改官方 DeepSpec 源码。

## 配置变化

- Target：主干参数 BF16 → FP16，AR 和所有投机方法一起变；Head 继续执行 FP32 GEMM。
- 只转换 `target.model` 参数，保留原 FP32 RoPE Buffer，避免简单 `.half()` 连 Buffer 一起降低精度。
- EAGLE3、DFlash、DSpark 的 Draft 参数/KV 仍为 BF16。三者实际源码都在 `draft.fc` 投影 Target 特征，在此边界将 FP16 特征转 BF16；不改变 Target KV 或接受算法。
- TF32 继续关闭。关闭 FP16 reduced-precision reduction；BF16 reduced reduction 保持原设置。这是明确记录的新配置，不是纯粹只有 dtype 改变的单变量因果实验。
- 不增加 CUDA Graph、固定 Linear 行数、per-query Attention 或新的阈值，不改变原一致性判定。
- 从现有十二条正式工作负载中按原 Token ID 取 `humaneval:19`、`humaneval:4`、`mt-bench:9`；每条 256 输出、ignore EOS、一轮；三个独立配对 AR 及七个模式共 30 次请求执行。先前 BF16 记录的总生成耗时按规模估算约 3～5 分钟，另计模型加载、预热和权重核验；不是运行时间保证。

代码：`precision.py::configure_target_backbone()`、`install_draft_feature_bridge()`、`configure_target_head()`；`benchmark.py::worker()` 在预热之前配置。输出记录和汇总同时检查各 worker 的 dtype、Head 和 Draft 边界配置。

本地 CPU 检查覆盖 Buffer 保留、真实 FP32 Head、FP16→BF16 投影、协议错配拒绝及请求选择。2026-10-21 的 [GPU 结果](../../results/speculative_compare/fp16-regression-20261021/README.md) 为 20/21 组投机请求一致，仅 Confidence 0.8 的 `mt-bench:9` 在索引 24 分叉；整体仍未通过。下一步 [复用旧 Target 算术](LEGACY_TARGET.zh.md)，不是继续盲目重跑此入口。

FP16 有更细的有效数精度，但动态范围小于 BF16；换 dtype 不会恢复原 BF16 checkpoint 已经舍掉的权重信息。它改变后续算术和 KV 的表示，不能保证所有 Prompt 都逐 Token 一致。即使这三条通过，也只说明本短对照通过，正式十二条三轮仍需另行授权/验证。

## 服务器运行

将独立包上传到 `/hy-tmp/minivllm-work/`，解压后运行新目录的 `run_fp16_regression.sh`。入口自动寻找与归档十二条输入完全相同的原正式 `prepared/lock.json` 或 `measured/lock.json`，继承模型路径、权重及源码指纹、种子，不重新准备模型。

如果原正式目录改名，可以在启动前指定 `SOURCE_LOCK=/实际旧正式目录/prepared/lock.json`；它仍会核对输入是否与归档一致，不能用之前只有三条、32 Token 的 Smoke lock 替代。

新运行目录为 `results/speculative-fp16-regression-*`，指针 `results/speculative-fp16-latest.txt`。原 BF16 目录、原启动脚本和结果不覆盖。日志结尾 `QUALIFIED GREEDY COMPARISON: True` 才表示所有短对照通过；False 仍完整保留并打包 Token ID、接受轨迹、精度配置和源码。三轮旧数据的分叉汇总见 [分析报告](../../results/speculative_compare/divergence-20261019/README.md)。
